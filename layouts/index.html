go-opentype is a family of pure-Go, standard-library-only packages that together read a font file, lay out Unicode text — including mixed-direction and Arabic script — and rasterise the result, with zero third-party dependencies anywhere in the stack.

import (
    "github.com/go-opentype/opentype"
    "github.com/go-opentype/shape"
)

f, _ := opentype.Parse(ttf)   // ttf is a []byte TrueType/OpenType blob
face := f.NewFace(32)         // 32px per em

for _, g := range shape.Shape(face, "بيت", shape.Options{}) {
    // g.GID              glyph to draw
    // g.XAdvance, g.YAdvance   advance to move the pen by (px)
    // g.XOffset, g.YOffset     placement relative to the pen (px)
}

bounds, mask, maskp, advance, ok := face.GlyphMask('H', penX, baselineY)

What it replaces: the narrow slice of golang.org/x/image/font + font/opentype a glyph-blitting UI needs, and golang.org/x/text/unicode/bidi — both dropped in favour of a smaller, purpose-built, dependency-free stack. The long-term aim is functional parity with the HarfBuzz + FreeType pair on the paths this stack covers; today that's TrueType outline parsing/rasterisation, UAX #9 bidi, and Arabic + Latin/default shaping — CFF/CFF2 outlines, full GSUB/GPOS, hinting and variable fonts are tracked as roadmap, not yet shipped.

Every package in the stack ships with a 100 % statement coverage gate, tested against synthesised in-memory fonts so no package depends on an external .ttf to run its suite. The whole stack is pure Go with cgo disabled — no C toolchain, no runtime fetch, no vendored assets — and cross-compiles trivially, including to GOOS=js GOARCH=wasm. Everything is BSD-3-Clause.
